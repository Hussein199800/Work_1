## ⚠️ RULE #1 — NEVER LOSE THE USER'S DATA
The user's real production data exists in ONE place only: the browser `localStorage` of the live site above (origin `hussein199800.github.io`). There is no server or other copy. The user considers this the most important rule of the project.

Every change (add, edit, delete, refactor) must keep existing data loading correctly after deploy:
- Never rename, remove or repurpose existing storage keys: `audit_users`, `audit_prices`, `audit_addition_prices`, `audit_addition_stamp_status`, `audit_transport_settings`, `audit_stamp_prices`, `audit_records`, `audit_records_store`, `audit_price_schedule`, `audit_committee_shares`, `audit_committee_rates`, `audit_council_share`, `audit_council_saved`, `audit_record_draft`, `currentUser`, `activeSection`.
- **Records may live in IndexedDB** (db `audit_db`, store `kv`, key `audit_records`) — the user's real data hit the ~5M-char localStorage quota (≈9.3 MB, ~4000 agencies) on 2026-10-15. When `localStorage.audit_records_store === "idb"` the records are ONLY in IndexedDB. `index.html` reads them before injecting `script.js` (`window.__AUDIT_IDB_RECORDS`). All record writes go through `persistRecords()` (Promise) — never `saveData("audit_records", …)` directly. `moveRecordsToIDB()` writes, reads back and compares before setting the marker and only then removes the localStorage copy; it runs automatically when records exceed `RECORDS_MOVE_THRESHOLD` (after downloading a backup) or on a quota error. If IndexedDB can't be read, `recordsLoadFailed` blocks every save. Never delete the IndexedDB database. Use `onReady()` instead of `DOMContentLoaded` (script.js is injected after the page loads).
- Never call `localStorage.clear()` or remove data keys; never overwrite saved data with defaults.
- Data shape changes must be additive and backward compatible: read old records as they are (default missing fields at read time), migrate in place without dropping fields.
- Keep the backup/restore format (`downloadBackup` / `restoreBackupFromFile`, `version: 1`) able to read older backup files.
- Do not rename the repo, change the Pages URL/domain, or move hosting — a new origin means an empty `localStorage` (data looks lost).
- Before pushing anything that touches loading/saving/records, tell the user to download a backup (النسخ الاحتياطي) from the live site first, and confirm before pushing to `main` (pushing deploys to the live site).

## Overview
Arabic (RTL) single-page web app for auditing records and agencies. Plain HTML/CSS/JS — no build step, no backend, no package manager. Open `index.html` directly in a browser.

- `index.html` — all pages/sections (login, dashboard, records, new record, reports, committees, calculator, guide, prices, users, modal, print root).
- `style.css` — all styling (IBM Plex Sans Arabic, Tabler icons webfont).
- `script.js` — all logic (~14k lines, `"use strict"`). Not split into modules on purpose: it is injected by the loader after reading IndexedDB; any split must keep that order (see `docs/ARCHITECTURE.md`). Sections are separated by `/* ===== ... ===== */` banner comments with Arabic titles.

## Domain
- Agency types and default prices live in `DEFAULT_PRICES` / `AGENCY_NAMES` at the top of `script.js` (general, special, legal, executive, certified_general_special, certified_legal). Default type when adding an agency: `special` (`DEFAULT_AGENCY_TYPE`).
- Additions (`ADDITION_NAMES`): حفظ، توقيع إضافي، إضافة إلى التركة، ولاية…
- بدل الانتقال: added automatically for المندوب الخارجي **only** to general/special/legal (`TRANSPORT_AGENCY_TYPES`); never to certified copies or executive; not charged on cancelled agencies.
- Committee shares (لجنة الإسعاف ولجنة التعاون) are computed **by the agency's date** (`getAgencyCommittee(agency, day)`, 2026-10-21 at the user's request): the agency's period = its `pricePeriod`, else its record date (callers pass `getRecordDay(record)`; `sumCommittees(agencies, day)` looks the record up via `agencyDayIndex()` when agencies come from several records), else `appliedPrices.priceMonth`. In that period's row of «أسعار حسب الفترات», an explicit amount (`prices[type].ambulance` / `.cooperation`, optional additive fields, empty cell = absent) wins; otherwise period agency price × the type's percentage (`committeeRates`, key `audit_committee_rates`); with no period, stored `basePrice` × percentage. Reports show the per-agency amount actually used (`shareAmountsText`), not a percentage. First run derived the percentages from the old fixed amounts ÷ price (300 ÷ 1700 = 17.647%); `audit_committee_shares` is kept in sync for compatibility. Amounts round to the nearest pound.
- Agency type keys on the new-record page (`AGENCY_TYPE_KEYS`, by `event.code` so they work with the Arabic layout): F عامة, G خاصة, H شرعية, V تنفيذية, B مصدقة عامة/خاصة, N مصدقة شرعية — no modifier, only when focus is the agency number, a numeric item field or no text field; focus stays put; a `<kbd>` badge shows on each chip.
- Short record report («التقرير المختصر») prints in 2 pages for a heavy record (60 agencies, 20 notes): notes grouped (one line per note text with its agency numbers, `groupAgencyNotes`), types + transport side by side, tighter print CSS under `#printRoot .doc-summary`, zero rows hidden in print only; signatures kept.
- Agency/record grand total = agency price + additions value (cash + stamp-type additions × pleading stamp price) + full transport allowance (`getAgencyGrandTotal`, `getRecordGrandTotal`).
- Numbers and dates use Western digits (`NUMBER_LOCALE`). Numeric inputs are `type="text" data-num` (not `type="number"`, which the browser renders in Arabic-Indic digits); `number()` accepts Arabic-Indic digits and thousands separators.
- UI messages use `notify()` / `flashNotify()` / `appConfirm()` / `appChoose()` (multi-choice) — never `alert()` / `confirm()`. Dialogs resolve on button click, not on the `close` event (it can be delayed).
- Period prices (`priceSchedule`, key `audit_price_schedule`: `[{from:"YYYY-MM-DD" (old entries may be "YYYY-MM" = 1st of month), prices:{type:{agency, representative}}}]`): `priceTableForDay(day)` picks the latest entry with `scheduleStart(from) <=` the record date, else base `prices`. `getPricingForType(type, day)` uses it. Saved agencies keep `appliedPrices` (also `priceMonth` = the entry start date). Changing the record date offers to reprice pending agencies (automatic ones only). `DEFAULT_PRICE_SCHEDULE` (the 2026 branch table: 1–4 Mar, 5 Mar, 1 Apr, 1 May, 14 Jun, 3 Aug, 1 Sep) is seeded ONLY when the key is absent — never overwrite a saved schedule. Only the main-office (المكاتب الرئيسية) columns are stored: external = same price + automatic transport. In May/June 2026 the user said 1900 is the price WITHOUT transport and both main and external offices paid transport — the user adds it from the transport field; do not add a "no transport" flag. البدائية = general + special; المصدقة البدائية = certified_general_special; حصة الفرع = representative.
- Per-agency price (`agency.pricePeriod`, additive, 2026-10-20): the user said one record can hold agencies at 2–3 different prices. Empty/absent = by record date; `"YYYY-MM-DD"` = that schedule entry; `"base"` = base prices. Picked in the agency form («سعر الوكالة», `#agencyPricePeriod`, sticky within a record, reset on a new record) or per pending row («السعر», `changePendingPeriod`). Use `pricingForAgency(type, period)` / `pricePeriodDay(period)`; never price an agency with the record date when it has a `pricePeriod`.
- Reprice saved records («تسعير السجلات المحفوظة حسب تاريخها» card on the prices page, `collectRecordReprice` / `applyRecordReprice` / `undoRecordReprice`): records saved before 2026-10-16 all got the single base price whatever their date, so their committee shares were wrong. The tool previews by period/type and lists records with checkboxes (the user unticks mixed-price records and fixes them by hand), skips cancelled agencies and those with `pricePeriod`, downloads a backup, asks, then changes ONLY `basePrice`, `representativeBase`, `representativeAmount` (by the same branch-share difference) and `appliedPrices.agency/representative/priceMonth`. Previous values go to `agency.priceHistory` (batch id); undo restores them exactly. Never run it automatically.
- Bulk price change («تغيير سعر وكالات محفوظة» card on the prices page under the committee card, `collectBulkPrice` / `applyBulkPrice`, 2026-10-21): pick saved agencies by record-date range, or one record + agency-number range (from/to), optional type; new price = a schedule period (sets `pricePeriod`) or a specific amount (sets additive `customPrice` / optional `customRepresentative`). Live preview (counts, price, branch share, committee totals before → after), backup download, confirm; only price fields change via the shared `applyAgencyPriceChange` (history in `priceHistory`, also restores `pricePeriod`/`customPrice`); touched records get `updatedAt` = now so sync treats them as newest. An agency with `customPrice` keeps it through type changes (`buildAgency` honours `inputs.customPrice`), is skipped by date repricing, and its committee shares = its own price × percentage (period explicit amounts ignored). Choosing a period from the pending row clears it. Undo (shared «تراجع عن آخر …» button) reverts the latest batch of either tool. Do not re-render the preview on `change` (blur of a text field would replace the apply button under the click).
- Safeguards added by the full review (2026-10-21, regression test `tests/review.mjs`):
  - Plain Enter in any record-form input never submits (keydown guard on `#recordForm`); saving is the button only.
  - Editing an agency is **in place** (`editingAgency`, `startAgencyEdit` / `endAgencyEdit`, `getEditedAgencyFromForm`): it stays in `pendingAgencies`, «إضافة الوكالة» replaces it at the same index with the same id, keeping `customPrice` and `priceHistory`; the sticky price period is restored afterwards. Saving the record while an agency is open is blocked with a message. `clearAgencyForm` ends the edit.
  - `editRecord(id, then)` asks before discarding unsaved form changes (`hasUnsavedRecordForm` / `confirmDiscardRecordForm`); the real work is `editRecordNow`. It resets the price period, pending undo and insert-shift state. «إلغاء» asks too.
  - Drafts: an unchanged opened record writes no draft; an edit draft stores `baseHash` (`recordVersionHash` of the record when editing began); restore asks if the record changed since, and drops the draft if the record was deleted (`applyRecordDraft`).
  - Ctrl+Z on an agency added by «إدراج وإزاحة» un-shifts the numbers (`lastInsertShift`); «تراجع عن الإلغاء» re-applies it.
  - Changing the record date and choosing «إبقاء الأسعار» pins each kept agency to its old period (`pricePeriod`), or `customPrice` if it had none, so committee shares match the kept price.
  - Cancelled agencies: additions keep their counts but compute to 0 (`buildAgency`), and the live preview shows no transport/additions for them.
  - Old-shape agencies (`missingStamps` instead of `stamps`, no `additions` / `additionValues`) are read with fallbacks everywhere — never assume those objects exist.
  - Two open tabs: every records save writes `audit_ui_records_rev`; a tab that sees another tab's save (or a records-store change) sets `recordsStaleTab` and `persistRecordsNow` refuses with a "reload" message.
  - Unreadable/corrupt `audit_records` text sets `recordsLoadFailed` (never start from `[]` over it). While `recordsLoadFailed`, every backup path refuses (`backupBlockedByLoadFailure`) so an empty backup never replaces today's good file.
  - Intentional reloads use `reloadApp()` (skips the unsaved-changes prompt) — never plain `location.reload()`.
  - Restore: a failed save puts memory back; restore is manager-only; with Firebase on, `fbResetAfterRestore()` makes the next sync a fresh first sync (union, no tombstones for records missing from the file; restored settings don't outrank shared ones).
  - `fbSync` commits base hashes for applied records only after the local save succeeds, and skips applying a record that was saved locally while waiting for the safety backup.
  - Reprice / bulk tools re-collect their agencies after the confirm dialog; undo restores `appliedPrices.priceMonth` exactly (absent stays absent).
  - Reports: agency copies on the reports page carry `recordDay` (used by `sumCommittees`); «عرض التفاصيل» skips cancelled agencies and transport cash; «عدد الإضافات» excludes transport; missing-stamp rows use each agency's saved stamp price (`missingStampTypeValue`); representative names are trimmed; the «3 أشهر» comparison uses an equal previous period.
- Records page filter/sort (`getVisibleRecords`, `recordsView`): period / rep type / office / sort + search, on a sorted COPY (saved record order never changes). UI pref key `audit_ui_records_view` (not data).
- «تطوير الموقع» page (`#devlogSection`, static HTML in `index.html`): timeline of stages and dates, crediting شذى البكور وباسل البكور (idea + first published version), حسين الطويل (development since the Work_1 repo, 2026-09-30) and Claude. Add a bullet/stage there when shipping notable features.
- Agency calculation is pure: `readAgencyInputs()` / `agencyInputsOf(agency)` → `buildAgency(inputs, pricing, keepId)`. Reuse it for repricing / type changes; don't duplicate the math.
- Adding an agency whose number already exists → `appChoose`: insert and shift every pending agency with number ≥ N by +1 (data untouched), or add as duplicate.
- «وكالة مماثلة» (`addSimilarAgency`) copies the last added agency's inputs with the next number; the row «النوع» select (`changePendingType`) rebuilds an agency with the new type; Ctrl+S (and Ctrl+Enter) adds an agency on the new-record page only.
- Saving a new record whose number already exists asks first (save as separate / open existing).
- Record auditors: `record.auditors` (array of 1–2 names, additive; old records have none → `getRecordAuditors()` returns []). Program-only: NEVER shown in reports/PDF. Last names pre-fill the next record (UI pref `audit_ui_last_auditors`); records filter `rfAuditor`.
- Auto backup (`autoBackupAfterSave` after every record save): writes `نسخة-احتياطية-YYYY-MM-DD.json` (same `version: 1` format as `downloadBackup`, via `buildBackupJSON`) into a folder picked once with `showDirectoryPicker` (handle in separate IndexedDB `audit_ui_db`/`handles` — never in `audit_db`); no folder/unsupported browser → auto-download once per day + reminder toast. `persistRecords()` and data-key `saveData` call `markDataChanged()`; `beforeunload` warns when changes are not backed up; sidebar `#backupStatus` shows the age. State is a UI pref `audit_ui_backup_state`.
- Telegram backup (`sendBackupToTelegram`, section «النسخ الاحتياطي إلى تليجرام» in script.js): after every backup (record save via `autoBackupAfterSave`, `backupNow`, `downloadBackup`) the browser posts the same `buildBackupJSON()` gzipped (`.json.gz`, CompressionStream) to `api.telegram.org/bot<token>/sendDocument` — a new silent message each time, one upload in flight (requests during it coalesce into one). «اكتشاف المحادثة» (`detectTelegramChat`) lists every chat that messaged the bot and saves a chat id ONLY after the user picks it in `appChoose` (several chats → none highlighted, so a stranger who found the bot is not picked by mistake). Bot token + chat id are a per-device UI pref `audit_ui_telegram` (NEVER in backups or the repo — the repo is public). Failures set `pending` and retry on `online` / next page load; success counts as a backup (`markBackupDone`). Without a folder, a successful Telegram upload replaces the daily auto-download. `restoreBackupFromFile` reads both plain JSON and gzip (`readBackupFileText`, magic bytes 1f 8b).
- Optional sequence check on record save (`checkAgencySequenceThen`, pref `audit_ui_seq_check`): missing/duplicate agency numbers → save anyway / review / save and turn off. Ctrl+Z (`undoLastAgency`) removes the last added agency (not while typing in a text field, except the untouched agency-number field), with «تراجع عن الإلغاء».
- Agency card = ONE screen at 100% zoom (user requirement): three columns `.agency-main` (number+status row, type chips, vertical notes `.grp-notes`, recap, buttons) | `.agency-summary` (the preview tiles, vertical, `.grp-summary`) | `#agencyItems`; ≤1280 two columns, ≤1024 one. Each group has its own tinted panel (`--grp-*` / `--grp-*-bg`), and an item with value > 0 fills with its group color (`.item-row.has-value`, text `--on-grp`). Focusing the agency number aligns the card to the top of the screen.
- Agency type chips: two rows — general/special/legal, then the less used executive/certified types (`buildChoiceChips(..., minor)`).
- Firebase sync (built 2026-10-20 at the user's request — section «المزامنة مع Firebase» in script.js, panel `#fbBox` in the backup card, full design in `docs/FIREBASE.md`): project `work-1-c2965`, Google sign-in, ONE shared workspace for the branch (`FB_WORKSPACE = "idlib"`, never change it once syncing started): Firestore `workspaces/idlib/records/{id}` (record as a JSON string + canonical hash + tombstone) and `workspaces/idlib/meta/settings`. The user wants Basel Albakkour to have exactly the same role (2026-10-20), so security rules allow a list of emails (Hussein + Basel); adding a person = adding an email to the rules. Emails are NOT in the repo — `docs/FIREBASE.md` has placeholders. Local data stays the source of truth; three-way sync per record using `audit_ui_firebase.base` hashes: only-local-changed → push, only-remote-changed → apply, both → newest `updatedAt` wins after a quiet safety backup, and a delete never beats an edit. First sync on a device downloads a full backup first. Settings: newest `settingsChangedAt` wins; never-edited settings rank by whether the device has records, so an empty new device never overwrites real prices; applying remote settings rewrites the keys then reloads (postponed while pending agencies exist). Sync runs after `persistRecords()` (debounced), on load if signed in before, on `online`, on returning to the tab, every 60 s while the tab is visible (incremental, cheap), and on «مزامنة الآن». If a remote change hits the record open in the edit form, a persistent warning offers «فتح النسخة الجديدة» (saving otherwise overwrites the other person's change); conflicts list the record numbers; never when `recordsLoadFailed`. Tests can inject `window.__FB_TEST_BACKEND`. Do not change the hash/canonical format without migrating `base` (it would re-push everything). The user dropped saving PDFs into fixed folders.

## Design system («الجواهر», 2026-10-16)
- The user asked to move away from white/blue: emerald (actions, `--accent`), royal plum (structure), burgundy (`--danger`, money gradient), muted gold (totals). Tokens at the top of `style.css` are semantic (`--heading`, `--text*`, `--surface*`, `--field`, `--accent*`, `--panel`, `--grad-money`…); legacy `--seal-*`/`--ink-*` are aliases. Use semantic tokens in new CSS.
- Light + dark themes: `[data-theme="dark"]` on `<html>`, set before render by an inline script in `index.html`, toggled by `toggleTheme()`, persisted in `audit_ui_theme` (UI pref). `.doc` / `#printRoot` re-declare light tokens so reports stay paper-white in dark mode and print.
- Fonts: IBM Plex Sans Arabic for everything; Noto Kufi Arabic only for page titles and the brand.
- Three breakpoints only: 1280 / 1024 / 640 px.
- Agency type colors (`AGENCY_TYPE_COLORS`) and the colored row stripes are an established convention the user relies on — keep them.
- Agency type/status are picked with colored chips (`buildChoiceChips`); the original `<select>` stays (visually hidden) as the value source — set `.value` then call `syncChoiceChips()` (already done inside `syncTransportField()`).
- Item groups have fixed colors everywhere: missing stamps = `--grp-missing` (burgundy), additions = `--grp-add` (gold), transport = `--grp-transport` (blue); classes `.grp-missing/.grp-add/.grp-transport`. Items live in ONE vertical column `#agencyItems` (`.item-row` per item, same input ids as before) beside the form; `QUICK_ITEMS` + `stepQuickItem` drive keyboard: Alt+1/2/3 missing, Alt+G/H/A/R/W/K additions, Alt+T transport, +Shift = −1; new-record page only). `syncQuickItems()` (called from `updatePreview`) highlights non-zero fields (`.has-value`) and renders the «هذه الوكالة» recap (`#agencyRecap`); pending rows show `agencyItemPillsHTML`. After adding, focus returns to the agency number.
- New-record page: sticky summary dock (`updateRecordDock`), Ctrl+Enter adds an agency, the add button ignores a second click within 700 ms. Plain Enter must NOT add (accidental duplicates are the user's main concern).
- Records table: «التقرير» + «تعديل» visible, the rest in the ⋮ menu (`openRecordMenu`).
- The only decorative motion is the seal "stamp" on the login page; everything respects `prefers-reduced-motion`.
- Brand mark (the user rejected the old circular seal): an open ledger with an "audited" ✓ badge on a rounded ink tile, built only by `sealSVG()`; colors via `--bm-tile/--bm-ink/--bm-badge/--bm-check` (sidebar uses a seal-blue tile); `mark-outline`/`seal-stamp` = no tile (watermark). In `index.html` marks are `<svg class="seal …" data-seal>` placeholders filled by `anchorSeals()`. The favicon is the same mark as an inline SVG data URI.
- Dashboard «نشاط الفترة» (`renderActivity`): period presets (this month / last month / 3 months / year / all, by record date), 5 stat tiles with % change vs the previous equal period, a single-series column chart (pure SVG, y-axis on the right for RTL, hover/focus tooltip, table toggle). UI pref key `audit_ui_activity_period` (not data).
- Global search (`openGlobalSearch`, Ctrl+K, sidebar/mobile button): records by number/office/rep and agencies by number (Arabic-Indic digits accepted); Enter opens the report / type view, «تعديل» opens the agency for editing.
- Quick audit (التدقيق السريع): in the record summary report every item — transport, missing stamps, each addition — opens `showAgencyAudit(recordId, filter)` listing only the agencies that contain it (any type), with their numbers in a strip for matching against the paper register and an edit button per agency. Filters: `transport`, `missing:<pleading|ambulance|aid>`, `add:<key>`.
- Roles: `manager`, `auditor`, `viewer`.
- Persistence: `localStorage` + IndexedDB on the device (source of truth), optional Firebase sync; backup/restore via the users section. Excel export via `xlsx-js-style` (CDN).
